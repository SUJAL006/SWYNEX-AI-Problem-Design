Task 1 · AI problem design

Classify dining-hall comments so the right owner sees them first

A practical, single-label classification problem with explicit go/no-go success criteria. Later tasks can wrap a public model API around this same contract.

Practical problem

Students type 1–3 sentences into a QR “How was your meal?” form. A dining coordinator currently reads every message and forwards it in Slack to kitchen, service, or facilities. Routing is slow and inconsistent, and cleanliness issues can sit in the pile.

AI task: given one comment, output exactly one label — food_quality, wait_time, cleanliness, or other — plus a confidence score. A person still decides what to fix. The model does not write replies.

User

Primary user
Dining operations coordinator for one residential hall.
Downstream
Kitchen lead, service lead, and facilities lead who receive labeled tickets.
Job to be done
Clear overnight comments on weekday mornings in under 15 minutes, without missing hygiene complaints.

Data

Closed set from one hall, one semester, existing QR form only. About 320 English comments (band 250–400), typically under 280 characters. Two staff raters label independently; the coordinator breaks ties. Strip names, emails, student IDs, and room numbers before any model call.

Examples are synthetic, not real student comments.

Four labels the system must predict
Label Meaning Example
food_quality Taste, temperature, missing items, dietary mismatch. “The lentil stew was cold and the rice was crunchy.”
wait_time Lines, slow restock, late station opening. “Grill line took 25 minutes at 12:40.”
cleanliness Spills, dirty tables, pests, unsafe surfaces. Highest operational priority. “Standing water and trays left on the floor by the dish return.”
other Praise, hours, mixed topics, or anything outside the three buckets. “Love the playlist. Please bring back oat milk.”

Constraints

  • One label per comment. Mixed comments become other.
  • No generated student replies, refunds, or public posts.
  • If top-class confidence is below 0.70, abstain and leave the ticket with the coordinator.
  • Predicted cleanliness always jumps the queue.
  • English only; other languages → other.
  • Hourly batch scoring is enough. Prototype may call a public AI API; production would need a campus data-processing agreement.
  • UI labels are words, not color alone; keyboard and screen-reader usable.

Success criteria

These bars decide whether the problem is solved. Task 3–4 evaluation examples should map to this table.

Go / no-go bars (80-comment frozen holdout)
Criterion Bar If we miss it
Macro-F1 ≥ 0.78 and at least +0.08 vs a keyword baseline. Do not claim the model is useful; keep iterating.
Cleanliness recall ≥ 0.90. Read every false negative. Do not ship auto-routing. Hygiene misses are worse than a slow inbox.
Precision (food & wait) ≥ 0.80 each, so the wrong owner is not paged. Keep human routing for those classes.
Abstain rate 10–25% of comments left unlabeled at the 0.70 gate. If <10%, the gate is too loose. If >25%, the coordinator still does all the work.
Time-to-route Median handling time under 15s (from ~45s) in a 10-day shadow test. The feature is a toy; do not turn on Slack auto-forward.
Label quality Cohen’s kappa ≥ 0.70 on a 50-comment double-rated slice before treating labels as gold. Fix the label guide; do not tune the model on noisy gold.

Ship routing only if cleanliness recall and macro-F1 both clear. Otherwise the prototype stays a search aid with full human triage.

What Task 2 can build

A small prototype that sends one comment to a model library or public AI API, parses a JSON label + confidence, abstains below 0.70, and shows the four labels in plain language. Task 3 adds error handling (timeouts, invalid JSON, empty input) and scored examples against the bars above. Task 4 packages that into a beginner-friendly app.

Out of scope for the whole track: campus-wide sentiment, automated student email, training on Yelp or social media, replacing health-department reporting.

Task 1 deliverable. Synthetic examples only. No student records.
